# Phase 3.5 — Visual Maps Integration: Report

Date 2026-11-13 · Implementer: Claude

## Features implemented

- **Versioned manifest + lazily loaded map documents:**
  - `public/maps/manifest.json` (`schema: 1`, `version`) plus one JSON document per map (`public/maps/<id>.json`);
  - each manifest entry carries `id`, `version`, Surah/Ayah range, `file`, `source`, `license` and a `review` status (`app_authored_unreviewed | teacher_reviewed`);
  - documents reference **canonical (surah, ayah)** only; validation rejects out-of-range references and **any embedded Quran text** (Arabic diacritics).
- **One engine:**
  - `src/lib/mapCatalog.ts` (`loadManifest`, `loadMap`, `mapsForAyah`, `validateMapDoc`) is used by both the existing Visual Maps page and the new in-lesson `MapCue`;
  - the three original maps stay bundled in `src/lib/mindMaps.ts` for offline use, with **stable IDs** `al-fatihah`, `al-baqarah-1-5`, `al-baqarah-21-29`;
  - their JSON documents are generated by `scripts/build-map-docs.mjs`, and a test fails if they drift apart;
  - maps listed only in the manifest appear in the catalog as "Load map" cards and are fetched on demand.
- **Map cues in learning** (`src/components/MapCue.tsx`):
  - guided-lesson steps, manual lessons and recovery lessons show the covering map's symbol, colour, cue and branch title for the Ayah, labelled *"Memory cue … — not Quran text or Tafsir"*, with "Open map";
  - **no map → nothing rendered**; lessons work identically without maps.
- **Mushaf link:** the map page's selected-Ayah panel now links to the exact Ayah in the Mushaf ("Open Al-Fatihah 3 in the Mushaf") and to "Learn this page".
- Deep links `/mind-maps?map=<id>&ayah=<n>` open a map at an Ayah.
- **Unchanged:** the existing map features (coloured branches, progressive reveal, hide/recall, cue matching, order exercise, 7 stages, print) and `mapProgress` records.
- **Mastery separation:** map quizzes still update only `mapProgress`. Only the existing learner-rated Practice "assessment" sessions write Hifz records. Tests confirm map progress — even "strong" — produces no coverage and no revision tasks.

## Third-party mind-map PDFs

**Not in the workspace** (a recursive search found no PDFs). Nothing was imported, traced or reproduced. A statement such as "وقف لله تعالى يهدى وينشر ولا يباع" was not treated as a commercial redistribution licence. The catalog now supports adding further **original, reviewed** maps as JSON documents (see `scripts/build-map-docs.mjs` header). **Content import remains blocked** pending licensed content and teacher review.

## Word meanings

No reviewed, licensed word-by-word glossary exists in the project. Word-meaning features stay **disabled and labelled** as awaiting reviewed content. Lessons show only the bundled Ayah-level translations.

## Remaining risks and blocked items

- **Content:** only 3 maps exist; their cues are app-authored and **not yet teacher-reviewed** (the manifest says so).
- **Blocked:** importing the user's PDF maps — they are not present and have no licence or permission.
- **Offline:** manifest-only maps need to have been fetched once while online before they work offline. The service worker's caching of `/maps/*` was not separately verified; the bundled three always work offline.
